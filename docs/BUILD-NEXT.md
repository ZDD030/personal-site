# 下一步：把主题变成个人网站

第一轮搭建先完成个人资料、五个常用页面和真实内容。沿用 Firefly 的界面与组件。

## 需要准备的资料

| 资料 | 用途 |
| --- | --- |
| 网站名称、公开昵称 | 标题、导航、作者署名 |
| 头像 | 个人卡片与关于页 |
| 一至三句简介 | 首页与个人卡片 |
| 愿意公开的 GitHub、邮箱等链接 | 联系方式；未提供的入口不显示 |
| 研究或学习方向、经历 | 关于页；仅发布用户确认的内容 |
| 项目简介及源码链接 | 项目展示，可先整理保研工作台 |

正式域名可后续填写，不影响本地搭建。

## 第一轮具体修改

1. 更新 `src/config/siteConfig.ts`、`profileConfig.ts`，替换主题作者资料、站名与介绍。
2. 调整 `navBarConfig.ts`，主导航收敛为首页、文章、随记、项目、关于。按用户喜好保留横幅和主题色；音乐、背景视频、公告、相册、留言及打赏等可选功能先精简。
3. 将上游演示文章、项目及动态移出公开内容目录保存为参考，避免显示成站主作品。整理 `src/content/spec/about.md`，补充保研工作台的真实项目介绍。
4. 加入用户提供的一篇文章和一条随记；先采用 Markdown 内容文件，验证代码块、数学公式、分类、标签与搜索。
5. 验证手机与桌面访问、导航、项目详情、文章正文、明暗模式、RSS 和生产构建；提交并推送到本站 GitHub 仓库。

第一轮验收时，所有公开资料属于站主，五个常用页面可正常访问，示例作者和演示文章不会混入真实内容，搜索能够找到已发布文章。

## 后续两轮

第二轮接入开源网页写作工具，完成登录、草稿、预览、发布、撤回，并确定内容更新与构建方式。此功能尚未实现，不能把 Firefly 的静态内容文件当作现成写作后台。

第三轮确定域名、服务器和备案，部署 HTTPS、版本更新与备份。个人站和保研工作台独立上线，通过不同域名入口访问。
